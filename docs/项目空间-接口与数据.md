# 项目空间 · 接口与数据（v0.1 示例版）

一个商机一个项目空间。顶部是业务主线（S1 需求引导 → S5 合同及履约），中部是项目群聊：成员和 AI 专家在主会话里协同，@ 到的专家在各自的**子会话**里执行任务，完成后把一句摘要发回群里。

- 前端：`apps/web/src/ProjectSpace.tsx`、`project-space.css`；入口 `/spaces`（左侧菜单“项目空间”），小Cue 首页的“项目空间待办”可直接进入对应空间或子会话。
- 后端：`apps/server/src/project-space/`（`service.ts` 业务逻辑、`routes.ts` 接口、`seed.ts` 示例数据）。
- 契约：`packages/contracts/project-space.ts`（阶段、角色、专家目录、类型和入参校验）。
- 测试：`tests/project-space.test.ts`。

## 数据

存在 `documents` 表，四个集合：

| 集合 | 主键 | 说明 |
|---|---|---|
| `project_spaces` | `PS-…` | 商机、客户名、商机名、赢单信心度（0–100）、主线阶段（S1–S5）、成员（人员带角色，专家带 `expertId`） |
| `space_threads` | 主会话 `<spaceId>:main`，子会话 `TH-…` | `kind: main / expert`，子会话记录专家、任务标题、状态 `running / done / failed`、摘要、错误 |
| `space_messages` | `MSG-…` | 作者（人员 / 专家 / 系统）、正文、@ 的专家；主会话里的子会话卡片放在 `card` 字段 |
| `space_todos` | `TD-…` | 标题、负责人、截止日、来源子会话、状态 |

CRM 商机阶段 S1–S8 建空间时映射到主线：S1→S1，S2→S2，S3→S3，S4/S5→S4，S6–S8→S5。之后主线阶段在空间内独立维护，不回写 CRM。

## 接口（均在 `/api` 下，沿用 Bearer 鉴权和统一错误格式）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/project-spaces` | 当前用户可见的空间，带进行中子会话数 |
| POST | `/project-spaces` | `{opportunityId}` 建空间；同一商机已有空间时直接返回它 |
| GET | `/project-spaces/:id?thread=` | 空间详情：空间、全部会话、当前会话消息、待办、模型是否已配置 |
| PATCH | `/project-spaces/:id` | `{stage?, winConfidence?}`，变更会在群里留系统消息 |
| POST | `/project-spaces/:id/members` | `{kind:'user',userId,role}` 或 `{kind:'expert',expertId}` |
| DELETE | `/project-spaces/:id/members/:memberId` | 移除成员（创建人不可移除） |
| POST | `/project-spaces/:id/threads/:threadId/messages` | `{content, mentions[]}`。主会话：每个 @ 的专家开一个子会话（未加入的自动加入）；子会话：继续追问同一专家 |
| POST | `/project-spaces/threads/:threadId/retry` | 失败的子会话重试 |
| GET | `/project-spaces/todos/mine` | 我在各空间的未完成待办（小Cue 使用） |
| PATCH | `/project-spaces/todos/:todoId` | `{status}` |
| GET | `/project-spaces/options/opportunities?q=` | 可建空间的商机 |
| GET | `/project-spaces/options/members` | 可邀请的人员 |

可见范围：成员、管理员，以及按 CRM 规则能访问该客户的人。

## 专家执行

- 专家用 `modelTurn` 调在线模型；系统提示包含专家职责、客户与商机、主线阶段、信心度、成员名单，以及主会话最近 12 条消息作背景。
- 回复最后一行「摘要：…」作为摘要：正文留在子会话，摘要写进卡片，并在**首次完成**时作为专家消息发回群里；子会话里的追问只更新卡片摘要，不刷群。
- 模型未配置或调用失败：子会话和卡片标为失败并写明原因，可重试；不使用固定模板回答。服务重启时未完成的任务标为失败。
- 前端每 3 秒轮询当前会话，实现多人同时在线看到更新。

## 示例数据

`seed.ts` 在 `OP-CATL-001`（宁德时代 · 储能项目，P9 主标对应商机）存在、且空间不存在时写入一次：6 位成员、4 位专家、3 个已完成的子会话（否决项与保函、效率与测点、信心度与风险）和 4 条待办。不覆盖用户在空间里的任何操作。
