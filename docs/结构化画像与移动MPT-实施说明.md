# 结构化画像与移动MPT

2026-11-16，本地开发；不部署云端。分支`codex/structured-profiles-mobile-mpt`延续PR #28及前序本地功能基线。

## 数据与权限

使用SQLite的`profile_documents`集合保存固定模板结构，`profile_document_versions`保存版本。模板在`packages/profile-template.ts`，模型不能扩展字段。分为本人个人画像、客户共享画像、用户×客户经营关注、项目共享画像、用户×商机个人画像。

项目八个模块中，身份范围、业务背景、MPT及S1–S4情况共享；关键关系竞争、事实风险未决事项、关注推进计划、时间线来源按用户独立。客户只有“我的经营关注”私有，其他模块共享。个人画像仅本人可读写，包括管理员不能通过新画像接口读取其他人的个人画像。

沿用CRM当前对象可见性；共享内容由对应负责人或管理员明确维护。CRM基础字段实时引用，不从个人聊天自动发布共享内容。字段维护校验版本；新增、修正、停用分开处理，旧异步结果不能复活停用项或覆盖较新的人工内容。

旧`memories`和16维`project_portraits`按本人懒导入，原记录与历史不删除；不把历史个人内容自动发布到共享。现行PC MPT阶段与矩阵功能保留。销售确认新的MPT评估后，仅共享定位，不共享其回答原话、私有重点事项或历史；原有历史定位可由负责人明确发布。

## 对话与持久化

普通对话按需读取个人画像，回答后提取明确长期偏好；不自动关联商机。商机对话读取个人、相关客户、共享项目及本人项目内容。关键词和预算控制上下文，历史变化只在相关问题中带入，停用项不作为当前内容。

`updateStructuredProfilesSkill`为固定字段、来源校验的持久化Skill，收据在`profile_skill_receipts`。只处理当前用户原话，系统委托、助手建议、问题或其他项目陈述不能成为当前项目事实。自动更新仅本人内容；共享维护及MPT确认沿用明确操作，不增加逐轮通知。

任务在`profile_capture_jobs`记录；服务重启后恢复未完成提取，失败最多重试3次。`profile_projection_jobs`跟踪MD投影失败并重试。Markdown位于`MEMORY_ROOT/structured/用户/类型/对象/`，含当前`Profile.md`及版本副本；SQLite为主数据，投影失败不回滚已保存业务版本。MD导出由鉴权后的数据生成，不接受任意文件路径。

## 页面与移动交互

- “记忆管理”入口改为个人画像、客户画像、项目画像三个固定模板视图，原独立项目记忆入口取消。
- 商机基础信息及PC领航员侧栏增加“项目画像详情”，显示共享/仅自己、最近更新、固定字段、来源及个人历史，可维护本人字段和有权维护的共享字段。
- PC原“查看项目画像”仍打开MPT阶段与矩阵；原评估、阶段修改和事项确认入口保留。
- ≤820px的商机会话在项目标题下显示移动MPT栏：项目画像详情、MPT画布、开始/继续评估或更新MPT。
- MPT评估为移动全屏表单，阶段单列、状态紧凑选择、情况输入、问题切换、暂存续答及明确保存。固定重点事项、未知与不涉及规则沿用原逻辑。
- MPT矩阵保留完整36格，在容器内横向滑动；当前定位高亮，点选查看策略。T采购阶段在移动端纵向显示，页面本身不产生横向溢出。
- 画像详情为移动全屏，字段维护为底部表单；PC为双列详情弹窗。两端保存MPT后同步刷新定位。

## 本地数据保护与验证

启用新服务前使用SQLite一致性快照备份到忽略目录`runtime/backups`，确认无活动运行后重启本仓库服务；没有重置或覆盖现有业务数据。

新增测试覆盖共享与个人隔离、管理员个人画像边界、字段白名单、版本冲突、原记忆导入幂等、来源与系统消息隔离、停用保护、共享MPT、提取任务恢复及MD故障恢复。

验收记录：完整205项、便携195项、构建通过；全量浏览器42条通过，最终任务恢复和共享版本变更后另复测4条画像/MPT旅程通过。便携测试不包含原生PPT运行时。另在隔离合成数据中调用真实模型验证普通对话个人偏好提取、Skill存储及未关联项目。截图与真实模型检查结果保留在忽略的`runtime/reports`，不提交可能含用户信息的运行资料。
