# 赢单领航员：手机简答与渐进追问

2026-11-24。本轮更新本地对话行为，PC与手机使用同一简洁回答规则，不改写历史回答、CRM或已有画像。

## 默认回答

针对“分析现状、下一步怎么推进”，仅展示：

1. **结论**：一句话指出当前优先方向。
2. **项目简述**：2–3句说明影响当前判断的事实，区分用户陈述、已核实和未知。
3. **推进建议（待办）**：最多3项，写清找谁、做什么、预期产出。

目标250–400字，校对上限600个可见字符；英文名称与单位会计入字符。默认不使用宽表格、完整证据/风险盘点、执行节奏或重复总结。用户明确要求详细展开时允许更长；明确索要表格、图表或特定交付物时按本次请求呈现。

每轮可自然追问**一个**会改变下一步判断的关键事实。先查当前输入、历史与画像，已答内容不重复问；模糊回答再聚焦主体、实际结果、剩余条件中的一个。用户不知道时给向客户核实的路径，继续可并行推进的动作，不因资料不全暂停全部工作。无需每轮机械追问。

正文追问向销售核实事实；“猜你想问”是销售委托AI工作的建议，二者分开，后者最多3项。已存在的后台画像采集机制继续记录用户原话及来源，不将AI建议当作用户确认事实，不自动更改MPT或CRM阶段。

手机端待办操作区只显示行动标题和添加按钮，避免重复展示正文里的长描述；打开创建窗口后仍保留完整可编辑描述、截止日期和确认步骤。

## 内部资源按需开启

仅看**本轮明确请求**，例如“需要内部资源支持，找谁协调”“请协调PD支持技术澄清”。单纯讨论资金缺口、客户联系人、项目风险、旧资源对话或画像中的资源信息都不算资源请求；明确否定资源支持时不开启。

没有请求时：

- 不将递资源知识加入本轮知识检索结果，领航员资源上下文为空。
- 生成与校对都禁止主动推荐内部部门、专家、归口、申请渠道及“资源待补”说明。
- 过滤隐藏待办及后续建议中的主动资源推荐。

有明确请求时再提供相关角色、申请输入和预期产出；对接人或授权未核实，不能编造姓名、链接和可用排期。客户侧联系人仍可正常用于销售推进待办，不被误当成内部资源屏蔽。

## 实现与验证

- `navigator-reply.ts`集中定义本轮意图、行动/篇幅限制与渐进追问策略；领航员上下文、生成、答案编辑和后续建议共用规则。
- 提示词版本升级到v6；答案编辑不再把短回答扩写为旧的900–1100字。
- 可执行待办仍使用原隐藏协议与确认创建流程。校对时保留绑定的行动对象与顺序，避免正文精简后按钮变成另一组任务。
- 不自动重写旧会话；重新发起分析或继续对话后应用新规则。

验证：完整219项、便携209项、生产构建；Chrome下5条手机简答、PC/手机输入区、MPT/画像、活动准备与确认旅程通过。原活动准备测试已改为从对话明确委托，不再引用早先已移除的“常用工具”。

在线模型验证仅使用**全新数据库中的公开虚构seed数据**，以Gulf Industry · Dubai Jebel Ali为场景：普通分析466字符、3项行动、3个后续建议，资源上下文0行；明确请求资源后472字符、3项行动、3个后续建议，资源上下文8行。两种结果均无剩余样式问题。此验证不代表已向模型提交本地真实历史。

真实历史的外部模型验证被自动审批拦截，未执行；没有通过其他路径重试发送，后续改用上述合成数据完成验证。原有用户数据库、会话和画像均未重置。本轮不部署云端。
